> 평가자용 문서, v1.3 (2026-10-16)
> - 평가자가 지원자 제출물을 직접 실행하고, 코드와 문서를 읽어 채점합니다.
> - 같은 폴더의 `solution/`(정답 서버)을 함께 사용합니다.

---

## 1. 평가 원칙

1. 모든 항목에는 ID, 판정 질문, 증거 위치, 판정 방법, 수준별 기준이 있습니다.
2. A 영역은 평가자가 서버를 실행하고 요청을 보내 확인합니다. B, C, D 영역은 코드와 문서를 읽고 판정합니다.
3. 판정은 증거를 근거로 합니다. 근거가 된 파일과 위치, 또는 응답 내용을 함께 기록합니다.
4. 판정이 애매하면 낮은 수준을 주지 말고 **판정 보류**로 표시한 뒤 이유를 적습니다.
5. 이 과제는 정확성과 설명 능력을 봅니다. 그래서 정확성(A)과 테스트 작성(B)의 비중이 가장 크고, 서술(C)이 그다음입니다.

## 3. 평가 절차

### 3-1. 사전 확인

| 확인 항목 | 기준 | 실패 시 |
|---|---|---|
| 실행 | `./gradlew bootRun`으로 8080 포트에서 실행됨 | **A 영역 0점**. B~D는 코드와 문서로 평가 진행 |
| 지원자 테스트 | `./gradlew test` 실행 결과를 기록 | B4에 반영 |

### 3-2. 평가 순서

1. `./gradlew test`를 실행하고 결과를 기록합니다.
2. 서버를 실행하고 4장의 확인 방법에 따라 S1~S12를 실행합니다. 지원자 저장소의 `requests.http`와 curl을 사용합니다.
3. A 영역 점수를 매깁니다.
4. 테스트 코드를 읽고 B, 서술을 읽고 C, 코드를 읽고 D를 판정합니다.
5. 치명 오류가 있는지 확인하고 감점을 적용합니다.
6. 평가 결과를 9장의 양식으로 기록합니다.

> **동시 요청 보내는 방법 (A3~A5, A9, A11)**
> - 셸에서 `for i in $(seq 1 10); do curl -s -X POST ... & done; wait`처럼 `&`를 붙여 요청을 동시에 보냅니다.
> - 응답 코드별 개수와 `GET /api/v1/users/{userId}/limit`의 사용액을 확인합니다.
>
> **정답 서버와 비교하는 방법**
> - 판정이 애매하면 `solution/`을 실행하고 같은 요청을 보내 기대 동작을 확인합니다.

| 상 | 5 | 단계(면제, 수수료율 결정, 감면, 버림과 최소 수수료, 최대 수수료)나 규칙 단위로 **나뉘어 있어** 표와 코드가 대응됨. 정수(bp) 등 **오차 없는 계산**을 사용함 |
| 중 | 3 | 결과는 맞지만 한 메서드에 조건이 몰려 있거나 `double`로 계산함 |
| 하 | 1 | 기존 코드 구조를 그대로 두었거나 중복과 하드코딩이 많음 |

### D2. 동시성 처리 구조 (4점)

- **판정 질문**: 동시성 처리 코드가 한곳에 모여 있고 락 범위가 분명한가?
- **증거 위치**: 승인 및 취소 서비스 코드

| 수준 | 점수 | 기준 |
|---|---|---|
| 상 | 4 | 락 범위(사용자 단위 락, 결제 ID 선점)가 **서비스 계층에 분명하게** 구현되어 있고, 컨트롤러에는 로직이 거의 없음 |
| 중 | 2 | 동작은 하지만 락 코드가 여러 곳에 흩어져 있거나 범위가 지나치게 넓음 (예: 전역 락) |
| 하 | 1 | 컨트롤러에 로직이 몰려 있음 |

- 전역 락도 정당한 선택이므로 정확성(A)에서는 감점하지 않습니다. 서술에 이유가 있으면 C2에서도 인정합니다.

### D3. 에러 응답의 일관성 (3점)

| 수준 | 점수 | 기준 |
|---|---|---|
| 상 | 3 | 예외 처리기 등을 사용해 에러가 **공통 형식과 코드**로 일관되게 응답됨 |
| 중 | 2 | 대부분 일관되지만 일부 경로가 다름 |
| 하 | 1 | 응답 형식이 제각각임 |

### D4. 불필요한 변경 (3점)

- **판정 질문**: 과제와 관계없는 파일이나 코드를 바꾸지 않았는가?
  - 수정 금지 파일은 지원자가 고치지 않았다고 보고 별도로 검사하지 않습니다. 코드 리뷰 중 눈에 띄는 변경만 봅니다.

| 수준 | 점수 | 기준 |
|---|---|---|
| 상 | 3 | 과제와 관계없는 변경이 없음 |
| 중 | 2 | 관계없는 변경이 조금 있음 (불필요한 포맷 변경, 쓰지 않는 코드 등) |
| 하 | 0 | 수정 금지로 안내한 파일을 고친 것이 코드 리뷰 중 발견됨 |
