# 2단계 — 예외 처리와 수수료 규칙 (과제 2. 결제 한도 차감과 수수료 정책)

1단계 위에 **입력 검증, 상태 코드, 수수료 규칙 10개**를 얹습니다. 동시 요청 처리는 아직 없습니다.

```bash
./gradlew bootRun   # 포트 8080 (촬영 때는 --args='--server.port=8122')
```

## 추가하는 것

- `GlobalExceptionHandler`와 `ApiException`으로 에러 응답을 `{"code","message","paymentId"}` 형식으로 통일
- 입력 검증(400 `INVALID_REQUEST`): `PaymentRequest`의 `@NotNull`/`@Size`/`@Min`/`@Max`와 `@Valid`, 수수료 API의 금액 범위 검사, `application.yml`의 `accept-float-as-int: false`
- 결제 ID 중복 → 409 `DUPLICATE_PAYMENT` (취소된 ID도 재사용 불가)
- 한도 초과 → 422 `LIMIT_EXCEEDED` (거절한 결제는 저장하지 않으므로 같은 ID로 다시 요청 가능)
- 취소 → 200 / 없는 결제 404 `PAYMENT_NOT_FOUND` / 이미 취소됨 409 `ALREADY_CANCELED`
- 승인 요청 검사 순서: 입력 검증(400) → 중복(409) → 한도(422) → 승인(200)
- `FeePolicy`를 규칙 표 전체(R1\~R10)로 채움. bp 단위 **정수**로 계산해 소수 오차가 없음

## 여전히 하지 않는 것

**동시 요청 처리(락)**. 3단계(`../../solution/`)의 몫입니다.

## 실행하면 이렇게 됩니다 (8122 포트에서 실측)

### 순차 시나리오 — 전부 기대대로 동작합니다

| 확인 | 결과 |
|---|---|
| S1 정상 승인 (GOLD 국내 50,000원) | 200, `fee: 250`, `remainingLimit: 950000` |
| S2 순차 중복 | 409 `DUPLICATE_PAYMENT`, 사용액 50,000 그대로 |
| S6 한도 경계 1,000,000원 → 1원 → 취소 → 거절됐던 ID로 재요청 | 200 → **422** → 200 → **200** |
| S7 `amount` 0 / 음수 / 누락 / `grade` 오타 / 10.5 | 모두 400 `INVALID_REQUEST`, 사용액 0 (저장 안 됨) |
| S7 수수료 API `amount=0` | 400 `INVALID_REQUEST` ("amount는 1 이상 100,000,000 이하여야 합니다.") |
| S8 없는 결제 취소 | 404 `PAYMENT_NOT_FOUND` |
| S9 순차 이중 취소 | 409 `ALREADY_CANCELED` |
| S10 취소한 ID로 재승인 | 409 `DUPLICATE_PAYMENT` |
| S12 수수료 | README 6장 계산 예시 **8개 전부 일치**, 평가 기준표 A12 확인 벡터 **24개 전부 일치**. 승인 API의 `fee`도 같은 값 (GOLD 국내 50,000원 → 250, BASIC 해외 1,000,000원 → 28,000) |

### 동시 요청 — 여기서 깨집니다

| 확인 | 기대 | 실측 |
|---|---|---|
| S3 같은 결제 ID 10건 동시 | 200 1건, 409 9건, 사용액 50,000 | **10건 모두 200**, 사용액 100,000 (3회 모두 같음) |
| S4 다른 사용자 10명이 같은 ID로 동시 | 200 1건 | **10건 모두 200**, 10명이 각각 50,000씩 (합계 500,000) |
| S5 400,000원 3건 동시 | 200 2건, 422 1건, 사용액 800,000 | **3건 모두 200**, 사용액 400,000(2회) / 800,000(1회). 이어서 600,000원을 요청하면 또 200이 되어 **승인 합계 1,800,000** |
| S5 변형: 이미 600,000원 쓴 사용자에게 300,000원 3건 동시 | 200 1건, 422 2건 | 3회 중 2회 **3건 모두 200** (승인 합계 1,500,000), 1회만 200 2건·422 1건. 사용액은 세 번 다 900,000 |
| S9 같은 결제 취소 10건 동시 | 200 1건, 409 9건, 사용액 0 | **10건 모두 200**, 사용액 **-300,000**(5회 중 3회) / 0(2회) |
| S11 900,000원 승인 상태에서 취소와 200,000원 승인을 동시에 | 최종 사용액 0 또는 200,000 | 3회 모두 취소 200 + 승인 422 → 사용액 0 (우연히 지켜짐) |
| S11 변형: 같은 상황에서 100,000원 승인 | 최종 사용액 100,000 | 4회 모두 둘 다 200인데 사용액 **1,000,000** — 취소되지 않은 승인은 100,000뿐 |

깨지는 자리는 `PaymentService`에 주석으로 표시해 두었습니다 — "중복 확인과 저장 사이", "사용액 읽기·판단·쓰기 사이", "취소 상태 확인과 사용액 빼기 사이".
