# 1단계 — 정상 경로 (과제 2. 결제 한도 차감과 수수료 정책)

해설용 단계별 코드의 첫 번째입니다. **설계한 흐름이 도는지만** 확인합니다.

```bash
./gradlew bootRun   # 포트 8080 (촬영 때는 --args='--server.port=8121')
```

## 만드는 것

- 결제 승인: 사용액을 읽고 → 결제 금액을 더해 저장하고 → 수수료를 계산해 200으로 응답
- 결제 취소: 결제 기록을 찾아 → 사용액에서 빼고 → 상태를 `CANCELED`로 저장
- 한도 조회, 수수료 계산 API
- 수수료는 **기본 수수료율 1.00%(100bp) 하나만** 적용

## 일부러 하지 않는 것

| 하지 않는 것 | 언제 하는가 |
|---|---|
| 입력 검증(400)과 에러 응답 형식 통일 | 2단계 |
| 결제 ID 중복(409), 한도 초과(422), 없는 결제(404), 이미 취소됨(409) | 2단계 |
| 수수료 규칙 R1\~R2(면제), R3의 해외 3.00%, R4\~R7(등급), R8(고액 감면), R9(최소), R10(최대) | 2단계 |
| 동시 요청 처리(락) | 3단계 (`../../solution/`) |

## 실행하면 이렇게 됩니다 (8121 포트에서 실측)

| 확인 | 결과 |
|---|---|
| 정상 승인 (GOLD 국내 50,000원) | 200, `remainingLimit: 950000`, **`fee: 500`** (규칙 표는 250원) |
| 한도 조회 | 200, `usedAmount: 50000` |
| 승인된 결제 취소 | 200, 사용액이 결제 금액만큼 줄어듦 |
| 같은 결제 ID로 다시 승인 | **200** (409여야 함), 사용액이 50,000 → 100,000으로 두 배 |
| 1,500,000원 승인 | **200**, `remainingLimit: -500000` (422여야 함) |
| `amount` 0 / 음수(-5,000) | **200**, `fee` 0 / **-50** (400이어야 함) |
| `amount` 누락 | **500** (400이어야 함) |
| `amount` 10.5 | **200**, 금액이 **10으로 잘려** 저장됨 (400이어야 함) |
| `grade`를 `PLATINUM`으로 보냄 | 400이지만 본문이 Spring 기본 형식(`{"timestamp":...,"error":"Bad Request"}`)이라 명세의 `{"code","message"}`가 아님 |
| 없는 결제 취소 | **500** (404여야 함) |
| 같은 결제를 두 번 취소 | **둘 다 200**, 사용액이 두 번 줄어듦 (409여야 함) |
| 취소한 결제 ID로 다시 승인 | **200** (409여야 함) |
| 수수료 규칙 표의 계산 예시 8개 | **2개만 일치** (12,350원→123원, 999,999원→9,999원). 999원→9원(면제 아님), 1,000원→10원(최소 수수료 없음), VIP 국내 5,000,000원→50,000원(면제 아님), BASIC 해외 10,000,000원→100,000원(최대 수수료 없음) |
| 같은 결제 ID 10건 동시 | **10건 모두 200**, 사용액 50,000\~100,000 (3회 실행: 100,000 / 50,000 / 100,000) |
| 400,000원 3건 동시 | **3건 모두 200**, 사용액 400,000 (5회 중 4회) 또는 800,000 (1회) — 승인 합계 1,200,000과 맞지 않음 |
