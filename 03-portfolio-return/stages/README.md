# 단계별 구현 — 가상 포트폴리오 수익률 서비스

해설 영상에서 **한 번에 완성하지 않고 세 단계로 나눠** 만들어 가기 위한 코드입니다.
각 단계는 그대로 실행되는 프로젝트이고, 다음 단계는 앞 단계에 얹는 구조입니다.

| 단계 | 폴더 | 한 문장 |
|---|---|---|
| 1 | `step1-정상경로/` | 설계한 흐름이 도는지만 확인합니다. CSV도 계산도 예외도 손대지 않습니다. |
| 2 | `step2-예외처리/` | 데이터 정리, 검색·정렬·필터·페이지, 입력 검증, 계산 규칙을 채웁니다. 아직 시세는 요청마다 받아 옵니다. |
| 3 | `../solution/` | 외부 호출을 요청 경로 밖으로 빼냅니다. 주기 갱신·토큰 재사용·장애 대비가 한 번에 풀립니다. |

실행은 어느 폴더에서든 같습니다.

```bash
docker run -p 9091:9091 ghcr.io/donghyunkim-hi/portfolio-price-server:1.2.0   # 가상 시세 서버
./gradlew bootRun                                                            # 포트 8080
```

> 아래 표의 값은 모두 전용 시세 서버(포트 9391, 관리자 API로 가격 `A001=1000`, `A052=10.02`,
> 환율 `1350.25` 고정)를 띄우고 1단계 8131, 2단계 8132, 3단계 8133 포트로 실제 실행해 측정한 값입니다.

## 1단계 — 정상 경로

**만드는 것**: CSV 적재, 상품 조회, 포트폴리오 생성·조회·목록·수정·삭제, 시세를 받아 평가금액 계산.

**일부러 하지 않는 것**: 데이터 정리, 검색·정렬·필터·페이지, 입력 검증, 매입가 고정, 환율 환산,
버림·반올림, 주기 갱신, 토큰 재사용, 장애 대비.

## 2단계 — 데이터 정리, 검증, 계산 규칙

**추가하는 것**
- CSV 정리: 중복 코드는 먼저 나온 행만, 통화 `KRW`/`USD`, 상장일 `LocalDate`, 빈 위험등급 `null`(정렬 시 맨 뒤)
- 상품 조회의 검색·유형/통화/위험등급 필터(AND)·정렬·페이지, 포트폴리오 목록의 이름 검색·정렬·페이지
- `GlobalExceptionHandler`로 에러 응답 형식(`{"code","message"}`) 통일
  — 400 `INVALID_REQUEST`, 400 `UNKNOWN_PRODUCT`, 404 `PORTFOLIO_NOT_FOUND`, 503 `PRICE_NOT_READY`
- 계산 규칙: 매입가와 매입 시점 환율 고정, 금액 원 단위 버림, 수익률 HALF_UP 반올림, 오늘 손익(가정 G2)

**여전히 하지 않는 것**: 30초 주기 갱신, 토큰 재사용, 마지막 시세 보관(장애 대비).
시세는 **요청이 들어올 때마다** 시세 서버에서 받아 옵니다.

**실행하면 이렇게 됩니다** (실측)

| 확인 | 결과 |
|---|---|
| 상품 수 | **120** (130행 중 중복 10건을 경고 로그로 남기고 제외) |
| `query=A012` | 1건, `"가상 중소형 ETF 99"`(먼저 나온 행) |
| 통화·상장일 | 조회 결과 전부 `KRW`/`USD`, `yyyy-MM-dd` |
| `query=성장` / `query=a001` / `query=dividend` | **7건 / 1건 / 9건** (대소문자 무시) |
| `type=ETF&currency=KRW` / `riskLevel=5` | **35건 / 21건** |
| `sort=riskLevel,asc` 마지막 페이지 | 맨 뒤 **8건**이 모두 위험등급 `null` (가정 G5의 NULLS_LAST). CSV의 빈 위험등급 8행은 중복 코드 10개와 겹치지 않아 정리 후에도 그대로 남습니다 |
| `size=0`, `size=101`, `page=-1`, `sort=hack,asc`, `sort=code,sideways`, `type=STOCK`, `currency=EUR`, `riskLevel=abc` | **전부 400 `INVALID_REQUEST`** |
| 없는 상품 코드 | **400 `UNKNOWN_PRODUCT`** |
| 수량 0 / 1,000,001 / 1.5, 이름 `""` / 51자, `holdings` 0개 / 21개 | **전부 400 `INVALID_REQUEST`** |
| 같은 `code` 두 번 | **400** `"같은 code를 두 번 쓸 수 없습니다: A001"` |
| 없는 포트폴리오 조회·삭제, 숫자가 아닌 id | **404 `PORTFOLIO_NOT_FOUND`** |
| `A052` 4주, 매입가 10.02 → 현재가 10.50 (README 6장 예시) | `totalCost` **54118**, `totalValue` **56710**, `profit` **2592**, `returnRate` **4.79** — 명세 기대값과 일치 |
| `A001` 10주 + `A052` 4주, 1,000→1,200 / 10.02→10.50 | `totalCost` **64118**, `totalValue` **68710**, `profit` **4592**, `returnRate` **7.16** |
| 매입가 고정 | 시세가 바뀌어도 `purchasePrice` **1000 / 10.02 유지** |
| `PUT`으로 10주 → 20주 (가정 G1) | 평균 단가 **1100** = (10×1000 + 10×1200)/20 |
| 목록 `query=내` / `sort=name,asc` / `page=1&size=2` | 2건 / 이름순 / `totalPages` 2 — 정상 |
| **시세 서버 `ALWAYS_503`** | **상품 조회·상세·목록 모두 500** — 아직 깨집니다 (R6·S11 위반) |
| **포트폴리오 요청 4번(생성·상세·목록·상세) 동안 토큰 발급** | **8회** — 요청마다 시세와 환율을 따로 받아 오고 그때마다 발급합니다. 3회 측정 모두 토큰 8, 시세 4, 환율 4 (S10 위반). 상품 조회만 4번이면 환율을 부르지 않아 토큰 4회입니다. 요청이 없는 40초 동안은 0건입니다 |
| 시세 변경이 반영되기까지 | **0.6초** — 빠르지만 요청마다 외부를 부르기 때문입니다 |
| `GET /api/v1/products?size=20` 응답 시간 | **0.076 \~ 0.214초** |

> 촬영 포인트: 여기서 `POST /admin/failure {"mode":"ALWAYS_503"}`를 걸고 GET을 쏘아
> **직접 500을 내 보이는 것**이 3단계의 동기가 됩니다. 평가 기준표에서 "장애 중 GET이 5xx"는 큰 감점 항목입니다.
> 토큰 발급 로그(`시세 서버 토큰을 새로 발급받았습니다.`)가 요청마다 쌓이는 화면도 같이 보여 주면 좋습니다.

## 3단계 — 외부 호출을 요청 경로 밖으로 (`../solution/`)

**새로 생기는 클래스는 셋뿐입니다.**

| 클래스 | 역할 | 푸는 문제 |
|---|---|---|
| `PriceSnapshotStore` | 마지막으로 성공한 시세·환율 스냅샷 보관 | 장애 중에도 GET이 응답 (R6, S11) |
| `PriceRefreshScheduler` | 30초마다 갱신, 실패하면 예외를 삼키고 `markStale()` | 주기 갱신 (R4, S9) |
| `TokenCache` | 만료 직전까지 토큰 재사용, 401이면 한 번만 재발급 | 토큰 재사용 (R5, S10) |

핵심은 **읽기(요청)와 가져오기(외부 호출)를 떼어 놓는 것**입니다.
2단계까지는 조회 한 번이 외부 호출 두세 번이었고, 3단계에서는 조회가 메모리 읽기 한 번이 됩니다.

**실행하면 이렇게 됩니다** (실측)

| 확인 | 결과 |
|---|---|
| 계산 결과 | 2단계와 동일 (`totalCost` 64118 → 시세 변경 후 `totalValue` 68710, `returnRate` 7.16) |
| 시세 변경 반영 | **0~30초** (갱신 주기가 30초라 변경 시점에 따라 달라집니다. 3회 측정 4.9 / 15.0 / 28.9초. S9 기준 45초는 항상 통과) |
| 토큰 수명(120초)이 지난 뒤 시세 변경 | 갱신이 계속됩니다. 반영 시간은 위와 같은 이유로 0~30초입니다 (S10) |
| 시세 서버 `ALWAYS_503` 중 GET | 상품 조회·상세·목록 **전부 200** |
| 장애 중 생성(POST) | **201** (마지막 스냅샷으로 담김). 단 스냅샷이 **한 번도 채워지지 않은 상태**(서버를 띄우자마자 장애를 건 경우)라면 명세대로 **503 `PRICE_NOT_READY`** 이고, 그때도 GET 조회는 200입니다 |
| 장애 중 상세 응답 | 다음 갱신이 실패해야 알 수 있으므로 **최대 30초 뒤** `"priceStale": true`로 바뀝니다(실측 30.2초, 가정 G4) |
| `GET /api/v1/products?size=20` 응답 시간 | **0.003 \~ 0.008초** (2단계 0.076\~0.214초) |

> 촬영 포인트: 2단계로 되돌려 같은 `ALWAYS_503` 명령을 다시 실행하면 500과 200이 바로 대비됩니다.
> 응답 시간 차이(0.2초 → 0.003초)도 같은 화면에서 보여 줄 수 있습니다.

| S2 | 상품 정렬 | ✕ | **○** | ○ |
| S3 | 상품 필터 (AND) | ✕ | **○** | ○ |
| S4 | 상품 데이터 정리 (중복·통화·날짜) | ✕ | **○** | ○ |
| S5 | 포트폴리오 CRUD와 입력 검증 (400·404) | △ | **○** | ○ |
| S6 | 포트폴리오 목록 (검색·정렬·페이지) | ✕ | **○** | ○ |
| S7 | 매입가 고정 | ✕ | **○** | ○ |

| S9 | 시세 주기 갱신 (45초 안 반영) | △ | △ | **○** |
| S10 | 토큰 만료 — 갱신 지속 + 매번 발급 금지 | ✕ | ✕ | **○** |

**△는 통과했지만 맞아서 통과한 것이 아닙니다.**

- **S5**는 1단계에서 생성 201, 조회 200, 삭제 204까지는 나오지만 잘못된 입력이 전부 통과합니다.
- **S9**는 1·2단계에 주기 갱신이 없는데도 통과합니다. 조회할 때마다 외부를 부르기 때문에 "항상 최신"일 뿐이고,
  그 대가로 S11이 깨지고 토큰이 요청마다 발급됩니다. 3단계에서 주기 갱신을 넣고도 45초 안에 반영되어야 진짜 통과입니다.

> 촬영에서 꼭 짚을 지점입니다 — **"항상 최신이면 좋은 것 아닌가"에 대한 답이 S11과 S10입니다.**

### 시세 서버를 쓸 때 주의할 점 (실측)

- 가상 시세 서버는 **기본 설정에서 간헐적으로 503을 반환합니다** (`/v1/prices` 150회 중 **8회**).
  1·2단계는 외부 호출이 요청 경로 안에 있어서, 장애를 걸지 않아도 이 확률만큼 GET이 500이 납니다.
- 촬영 중 값을 고정하려면 관리자 API를 씁니다 (헤더 `X-Admin-Token` 필요).
  ```bash
  curl -X POST localhost:9091/admin/failure -H 'X-Admin-Token: admin-secret' \
       -H 'Content-Type: application/json' -d '{"mode":"NONE","transientFailureRate":0}'
  curl -X POST localhost:9091/admin/prices  -H 'X-Admin-Token: admin-secret' \
       -H 'Content-Type: application/json' -d '{"prices":{"A001":1000,"A052":10.02},"freeze":true}'
  curl -X POST localhost:9091/admin/fx      -H 'X-Admin-Token: admin-secret' \
       -H 'Content-Type: application/json' -d '{"rate":1350.25,"freeze":true}'
  ```
  `freeze: true`는 **지정한 코드만** 고정합니다. 나머지 119개는 30초마다 계속 바뀝니다
  (실측: A001·A052는 80초간 그대로, A002·A003은 계속 변동). 환율 `freeze`는 전체에 적용됩니다.
  상품 목록을 화면에 펼쳐 보일 때 지정하지 않은 상품의 `currentPrice`가 움직이는 것은 정상입니다.
- 1·2단계에는 `PriceClient.issueToken()`에 `시세 서버 토큰을 새로 발급받았습니다.` 로그를 남겨 두었습니다.
  발급 횟수를 화면에서 바로 셀 수 있습니다.
