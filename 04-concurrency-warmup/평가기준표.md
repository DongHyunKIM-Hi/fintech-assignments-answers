# 과제 4. 쿠폰 사용과 회의실 예약 평가 기준표

> 평가자용 문서, v1.3 (2026-10-16)
> - 워밍업 과제라 기준표도 짧습니다.
> - 평가자가 지원자 제출물을 직접 실행하고, 코드와 문서를 읽어 채점합니다.
> - 같은 폴더의 `solution/`(정답 서버)을 함께 사용합니다.

---

## 1. 배점 요약

| 영역 | 배점 | 판정 방법 |
|---|---|---|
| A. 정확성 | 70 | 평가자가 curl이나 IntelliJ HTTP Client로 아래 시나리오를 직접 실행 |
| B. 코드 품질 | 30 | 코드와 README를 읽고 판정 |
| **합계** | **100** | |

### 평가 순서

1. 지원자 서버를 `./gradlew bootRun`으로 8080 포트에서 실행합니다.
2. 2장의 시나리오를 실행합니다. 지원자 저장소의 `requests.http`에 순차 요청 예시와 동시 요청용 셸 스크립트 예시가 있습니다.
3. 코드와 README를 읽고 3장의 B 영역을 판정합니다.
4. 4장의 치명 오류가 있는지 확인합니다.

> **동시 요청 보내는 방법 (A2~A4, A7, A9)**
> - 셸에서 `for i in $(seq 1 5); do curl -s -X POST ... & done; wait`처럼 `&`를 붙여 요청을 동시에 보냅니다.
> - 응답 코드별 개수와 조회 결과를 확인합니다.
>
> **정답 서버와 비교하는 방법**
> - 판정이 애매하면 `solution/`을 실행하고 같은 요청을 보내 기대 동작을 확인합니다.

## 2. 영역 A. 정확성 (70점)

### A-1. 쿠폰 (35점)

| ID (지원자 README 시나리오) | 시나리오 | 배점 | 통과 기준 |
|---|---|---|---|
| A1 (S1) | 정상 사용 | 5 | 보유 쿠폰 중 할인액이 가장 큰 쿠폰이 적용되고 삭제됨 |
| A2 (S2) | 쿠폰 2장 보유, 동시 사용 요청 2건 | 10 | **2건 모두 200**, 서로 다른 쿠폰이 한 장씩 사용됨, 이후 조회하면 쿠폰 0장 |
| A3 (S3) | 쿠폰 1장 보유, 동시 사용 요청 5건 | 15 | **1건만 200**, 나머지 4건은 404. 200이 2건 이상이면 이 항목은 0점이고 치명 오류 F1에 해당 |
| A4 (S5) | 서로 다른 사용자의 동시 사용 | 5 | 서로 기다리지 않고 각각 정상 처리됨 |

### A-2. 회의실 예약 (35점)

| ID (지원자 README 시나리오) | 시나리오 | 배점 | 통과 기준 |
|---|---|---|---|
| A5 (S6) | 정상 예약 | 5 | 201 |
| A6 (S7) | 순차 요청에서 시간 겹침 | 5 | 두 번째 요청이 409 |
| A7 (S8) | 같은 회의실, 겹치는 시간 동시 요청 5건 | 15 | **1건만 201**, 나머지는 409. 201이 2건 이상이면 이 항목은 0점이고 치명 오류 F2에 해당 |
| A8 (S9) | 같은 회의실, 끝과 시작만 맞닿은 시간 (예: 10시~11시, 11시~12시) | 5 | 둘 다 201 |
| A9 (S10) | 다른 회의실, 같은 시간 동시 예약 | 5 | 둘 다 201. 한쪽이 막히면 감점합니다. 락 범위가 너무 넓다는 뜻입니다. |

## 3. 영역 B. 코드 품질 (30점)

| ID | 판정 질문 | 배점 | 기준 |
|---|---|---|---|
| B1 | 락의 범위가 적절한가 | 12 | 쿠폰은 사용자 단위, 예약은 회의실 단위로 좁게 잠갔는지 봅니다. 전역 락을 쓰면 A4와 A9를 통과해도 여기서 감점합니다. |
| B2 | 컨트롤러에 로직이 몰리지 않고 분리되어 있는가 | 8 | 동시성 처리 코드가 서비스 계층에 모여 있는지 봅니다. |
| B3 | README 설명 | 5 | 락을 어디에 어떻게 걸었는지 짧게라도 적혀 있는지 봅니다. |
| B4 | 수정 금지 항목 준수 | 5 | 저장소와 API 명세를 바꾸지 않았는지 봅니다. 별도로 검사하지 않고, 코드 리뷰 중 눈에 띄는 변경만 확인합니다. |

## 4. 치명 오류

| ID | 내용 | 처리 |
|---|---|---|
| F1 | 같은 쿠폰이 두 번 사용됨 (A3에서 200이 2건 이상) | A-1 쿠폰 영역 전체 0점 |
| F2 | 같은 회의실에 겹치는 예약이 동시에 두 건 이상 성공함 (A7에서 201이 2건 이상) | A-2 회의실 예약 영역 전체 0점 |
| F3 | 서버가 실행되지 않음 | A 영역 전체 0점. B 영역은 코드로만 판정 |

## 5. 인정하는 다른 풀이

- 전역 락 하나로 쿠폰과 예약 요청을 모두 차례로 처리해도 정확성(A)은 만점을 받을 수 있습니다.
- 다만 B1(락의 범위)에서는 감점합니다. 락 범위를 판단하는 능력이 이 과제에서 가장 중요한 학습 목표이기 때문입니다.
